# ChatGPT Work｜知遙小說 × 出版 × 影音 AI 工作室

## 目的

本文件定義 Jemora 在 ChatGPT Work／GPT Web 中使用的可重複工作流程。核心原則是：**ChatGPT Work 負責執行與編排；Jemora 負責保存 Canon、作品資料、版本與可重複使用的製作規則。**

> Work 是 ChatGPT 的工作模式／能力，不是 Jemora 自行安裝的外掛。若帳號介面提供 Work，直接在 Web 的 Work 中使用本流程；若帳號尚未提供該功能，仍可使用 Project／GPT／既有工具依相同 SOP 執行。

## 一、全域創作設定

- 作者筆名：**知遙**
- 預設語言：**繁體中文**
- 文風：細膩、流暢、具文學感，但不堆砌辭藻
- 重視：人物欲望、恐懼、矛盾、成長；因果與情節推進；畫面感；自然對話與潛台詞；心理與情緒
- 避免：流水帳、過度解釋、重複、無因果事件堆疊
- 最新使用者設定優先於舊設定
- 小說章節完成後，附上該章中文字數

## 二、六大可重複 Workflow

### 01｜新書創作

觸發語：`開始寫《作品名》`

執行順序：
1. 讀取使用者提供的背景、角色與既有設定。
2. 自動建立故事核心、世界觀、人物弧線、人物關係、核心衝突、主線、副線、伏筆、反轉與完整章節結構。
3. 不要求使用者先完成複雜 Prompt 或完整大綱。
4. 使用者說「開始寫」後，直接產出從第一篇／第一章到最後一篇／最終章的完整小說初稿，不逐章等待「繼續」。
5. 每章完成後標示中文字數。

### 02｜全書出版級校對

觸發語：`開始全書出版級校對《作品名》`

檢查：
- 角色姓名、年齡、生日、職業與關係
- 人物性格與人物弧線
- 時間線、事件順序與因果
- 世界觀規則與專有名詞
- 前後伏筆與反轉
- 場景空間與人物動線
- 對白、語氣、稱謂與潛台詞
- 重複句、贅字、病句與節奏
- 章節銜接與篇章節奏
- 愛情線、主線、副線是否互相支撐
- 改編後是否破壞原作 Canon

原則：不是只抓錯字，而是以「出版級全書一致性」重新檢查與整合。使用者提出修改後，重新整合全書，不只修改單一段落。

### 03｜出版製作

觸發語：`開始《作品名》出版工程`

流程：
1. 最終全文校對
2. 統一章節與篇章格式
3. 建立出版 metadata
4. 製作 DOCX
5. 製作 TXT
6. 製作 PDF
7. 製作 Kobo EPUB（若工作環境支援）
8. 確認各格式文字內容一致
9. 最後才製作封面與相關圖片

作者欄固定使用：**知遙**。

### 04｜GitHub／Jemora 同步

觸發語：`同步到 Git`、`放進 Jemora`

規則：
- 優先保存可版本控制的 Markdown、TXT、JSON、YAML、metadata、Prompt、SOP 與腳本。
- 大型影音檔、原始音檔與出版二進位檔依 Git LFS／外部儲存策略處理。
- 每次更新保留作品名、資產類型、章節／範圍、版本資訊。
- 重要變更寫入對應 docs／README 或作品 metadata。
- 不覆寫已確認的 Canon，除非使用者明確要求。

### 05｜小說 → 有聲小說 → 影音

觸發語：`開始《作品名》第X章影音製作`

流程：

小說 → 章節／場景解析 → Character Bible → World Bible → Visual Bible → Scene Sheet → Shot Prompt → 影像／影片 → 多角色語音 → 字幕 → 音樂／音效 → 合成 → 多平台輸出

目標：每章可製作成約 1 小時的電視劇式內容。

保留獨立輸出：
- 影片
- 音訊
- 字幕 SRT／VTT
- 音樂
- 必要的場景 Prompt／Scene Sheet

### 06｜研究／可重複工作

可將固定研究任務變成可重複執行的 Work／Scheduled Task，例如：
- 全球 Psychology × Medicine 議題雷達
- AI 小說製作工具更新
- Google Flow／影音工具研究
- 出版平台規則更新
- 小說 IP／影音製作流程檢查

研究結果必須區分：來源內容、外部研究、模型推論與使用者既有設定。

## 五、影像製作原則

Google Flow／其他影片工具只負責視覺化，不得反向決定小說 Canon。

生成前必須優先讀取：
1. Character Bible
2. World Bible
3. Visual Bible
4. Scene Sheet
5. Shot Prompt

重要角色與場景使用固定 reference／ingredients，降低跨鏡頭視覺漂移。

每個場景拆成多個 Shot，再進行組接與後製。

## 六、資產命名

統一格式：

```text
作品名_資產類型_章節或範圍_版本
```

例如：

```text
渡神_第001章_旁白_v1.mp3
渡神_第001章_字幕_v1.srt
渡神_第001章_影片_v1.mp4
作品_篇章_章節_Scene01_Shot01_flow_prompt_v01.md
```

## 八、完成判定

每一項大型工程都必須回報：
- 執行範圍
- 使用的版本／來源
- 已完成項目
- 待處理項目
- 發現的 Canon 風險
- 下一個可直接執行的步驟

出版完成的判定為：**全文校對完成 → 出版檔案完成且內容一致 → metadata 完成 → 使用者確認完稿 → 才進入封面與宣傳視覺製作。**
